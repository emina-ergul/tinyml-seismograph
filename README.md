# Notes

- my specific board STM32F407G-DISC1 specs (that I care about):
    - built around the STM32F407VGT6 32-bit Arm Cortex-M4 microcontroller
    - 1 MB of Flash memory and 192 KB of SRAM
    -  ST-MEMS 3-axis digital accelerometer
    - supports both IC2 and SPI but the accelerometer specifically is SPI
    - STM32CubeIDE compatible

- HAL library import (hardware abstraction layer) is an STM specific library

- In STM32CubeIDE USER CODE comment sections are protected code sections automatically generated by STM32CubeMX that are preserved when generating code with STM32CubeMX (stops code being deleted when you regenerate your project after changing something in the .ioc configuration file)



### Configuration

- There is more than one SPI circuit on the board. Since the sensor is wired to the pins of SPI1, I had to enable SPI1 in the .ioc, making CubeMX generate the required code (hspi1 struct, MX_SPI1_INIT()).

- I struggled to find which SPI mode to use for the sensor so tried SPI modes 0-3 and got a response on 0 by making an LED light up if the WHO_am_i reg was receievd.

- While the board does have a virtual COM port, it is not connected to the USART of the microcontroller (UM1472 7.3.3), so 2 solutions are to get a USART USB dongle or to use the boards micro USB port and configure to stream data, since it is connected to the boards USB OTG FS peripheral.

- The micro USB firmware configuration involved enabling the HSE set to 48mhz, enabling the USB hardware USB_OTG_FS to device only, adding the CDC class, and givign it some memory (heap size settings).

## Terms
- CubeMX: Graphical configuration and code generator tool for STM32 microcontrollers. Writes code for hardware configurations.
- SPI: serial peripheral interface.
- SCLK/SCK: SPI clock.
- SPI Bus: clock, MISO, and MOSI.
- clock edge: The moment the clock switches from 0-1 (rising) or 1-0 (falling). The edge used for sampling is set by CPOL and CPHA.
- CPOL: clock polarity, sets the clocks resting level between transfers (low = rests at 0, high = rests at 1)
- CPHA: defines whether to sample on the first or second edge.
- CS: chip select, dedicated wire per device to let it know its beoing addressed (One SPI bus can be shared by multiple devices).
- PE3: a regular GPIO pin the board wires to the accelerometer's CS input, controlled using code.
- GPIO: general purpose input/output (pins on chip).
- Full duplex: data moves on 2 separate wires, MOSI and MISO at the same time (1 bit sent and received per clock pulse).
- MOSI: driven by the controller to send data/commands to the peripheral.
- MISO: drievn by the peripheral to send data back into the controller.
WHO_AM_I: a standard read only reg for external devices like sensors containing a fixed device ID to tell you if communication works.

- bitwise OR: compares corresponding bits and returns 1 if one bit is 1 or 0, or 0 if both bits are 0.

- Nyquist's rule: to capture a signal of a certain frequency, you must sample at more than double that frequency. Half your sample rate is called the Nyquist frequency (e.g. 50hz if sample rate is 100hz), and it's the highest frequency you can accuratley record.

- HSE : high speed clock
- RCC: 
- USB_OTG_FS: USB on-the-go-full-speed, a USB interface that allows a device to switch between USB Host and USB peripheral without needing a PC host.
- USB CDC: USB communication device class, a standard USB spec that lets USB devices act as serial ports, modems, or network interfaces using built-in operating system drivers
